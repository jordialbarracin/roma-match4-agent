Problem Statement

The Precision Dilemma in Automated Evaluation

Standard LLM scrapers fail in competitive evaluations due to three hard barriers:

1. Strict Normalization

Graders require exact values only (e.g. Lisa Su, 2.34.2). Any conversational filler or labels result in an automatic 0.

2. The Necessity Test

Citations must be exact sets. Returning extra URLs, search dumps, or hallucinated sources destroys the score.

3. 30-Second Budget

Each query is an isolated CLI call. Loading models on every question causes immediate timeout disqualification.

Engineered for AMD ROCm

Dual-Engine Sovereign Architecture

🚀 Keyless Multi-Source Retrieval

Zero proprietary API keys. Combines DuckDuckGo Lite, Wikipedia REST API, and direct registry endpoints (PyPI, npm) via ultra-fast C-compiled lxml HTML parsers.

🛡️ Verbatim Substring Containment

Fail-closed policy: every candidate value is verified literally inside the cited page text. Ungrounded queries cleanly return {"answer": "", "citations": []}.

⚡ Resident VRAM Daemon

Keeps the model resident in memory on AMD Instinct GPUs, serving sub-second RPC queries to the /app/app.py CLI client.

🔒 Crash-Proof Atomic Writing

Writes an initial valid JSON immediately on invocation, then atomically replaces it upon completion via os.replace to prevent corrupt files on timeout.
